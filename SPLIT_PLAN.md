# SPLIT_PLAN — «Жильё» только в CRM + публичная страница «Подбор»

## Цель
Убрать каталог жилья с публичного сайта и сделать его закрытым рабочим инструментом в CRM: ежедневный автосбор из Chotot и Mogi с фильтром и склейкой дублей, сверху варианты с телефоном хозяина и кнопкой «Написать в Zalo». На сайте вместо каталога — услуга «Подбор жилья» с анкетой пожеланий в Telegram.

## Контекст
- Пользователь пишет по-русски, хочет короткие ответы. Перед коммитом и push спрашивать. Ничего не удалять: убранное переносить в `C:\AI_Projects\_Заметки`. Не читать `private/`, `.env`, ключи.

  - **Chotot**: API `gateway.chotot.com/v1/public/ad-listing` (cg 1010 квартиры, 1020 дома, 1050 комнаты; `region_v2=9057`, `area_v2=905701`, `st=u`). На странице объявления в `<script type="application/ld+json">` блок `@type: Person` с `telephone`, `makesOffer.priceSpecification.price`, `itemOffered.name/description/image/address`. Координат нет, только адрес-текст: геокодер Nominatim, не чаще 1 запроса в секунду (уже есть в сборщике, `geocode`, стр. 263). - «Рабочий номер Zalo»: автоматически проверить, что номер зарегистрирован в Zalo, нельзя. Критерий в плане: валидный вьетнамский мобильный номер (10 цифр, начинается с 03/05/07/08/09, из `+84` приводим к `0`), ссылка `https://zalo.me/<номер>`. Честно написать об этом ограничении в интерфейсе («номер есть, Zalo не проверен»).
- Фильтр «рабочих» вариантов: аренда, тип квартира/дом/комната, цена владельца 1,5–50 млн ₫ в месяц, есть фото, комнат разумно, площадь в пределах (`MAX_AREA_M2`), в границах Далата, не продажа, не посуточно, не коммерческая/отель/вилла-бизнес (слова-маркеры: homestay, khách sạn, hotel, nhà hàng, mặt bằng, văn phòng, kinh doanh, nguyên căn 10+ спален), не устарело (по дате публикации не старше ~60 дней или всё ещё в выдаче).
- Склейка дублей: ключ — тип + цена (±5%) + площадь (±3 м²) + комнаты + расстояние между точками < 150 м; либо одинаковый телефон + близкая цена. Объединённый вариант хранит все источники (`sources`) и ссылки, берёт лучший номер и больше фото.
- Модель данных нового листа «Жильё (CRM)» (колонки; один вариант = одна строка): `code`(постоянный номер из `state/codes.json`), `kind`, `title`, `rooms`, `area`, `ownerPrice`, `district`, `addressText`, `lat`, `lng`, `geo`, `phone`, `zalo`(да/нет по критерию выше), `seller`, `sources`(chotot,mogi,manual), `urls`(через пробел), `photos`(до 6 ссылок через пробел), `status`(active/removed), `firstSeen`, `lastSeen`, `price`(текущая), `pricePrev`, `manual`(да/нет), `note`. Старый лист «Объекты (админ)» пока не трогать.
- Проверки: `python -m py_compile` сборщика и `run_update.py`; сухой запуск сборщика с `--out` во временный файл без записи в таблицу; `node --check crm/app.js`; CRM в браузере на 375x812 (`preview_start` сайт из `.claude/launch.json`, имя `site`, python http.server порт 8765; CRM на `/crm/`).
